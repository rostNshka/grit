# Grit

> Инструмент для анализа GitHub-профиля разработчика. Оценивает активность, качество кода и вклад в open source, а затем даёт конкретные рекомендации по росту.

## 📖 О проекте

**Grit** — это веб-приложение, которое помогает разработчикам понять, как их профиль на GitHub выглядит глазами рекрутера или тимлида.

Что делает Grit:

- Считает **Score** (0–100) на основе метрик активности, качества кода и комьюнити
- Разбивает оценку по метрикам: коммиты, PR, звёзды, форки, языки, вклад в чужие репозитории
- Показывает **конкретные рекомендации** — что улучшить в первую очередь
- Позволяет **сравнивать профили** (свой с эталонным или с коллегой)
- Даёт **чат в реальном времени** для обсуждения результатов с наставником или тимлидом

Проект задуман как практическая площадка для изучения современной фронтенд-архитектуры: монорепозиторий, workspace-пакеты, глобальное состояние, WebSocket.

## 🏗️ Архитектура

Проект построен как **монорепозиторий** с использованием **npm workspaces** и **Turborepo**. Код разделён на независимые пакеты, которые связаны через workspace-зависимости и переиспользуются в основном приложении.

### Пакеты

| Пакет | Назначение |
|-------|------------|
| `@grit/ui-kit` | Переиспользуемые UI-компоненты (`Button`, `Input`, `Card`, `ScoreCircle`, ...) с изолированной разработкой через Storybook |
| `@grit/toolkit` | Хуки (`useDebounce`, `useLocalStorage`), утилиты (форматирование Score, работа с датами), общие хелперы |
| `@grit/types-kit` | Базовые TypeScript-конфиги, общие типы и контракты API |

### Основное приложение `web`

- **Vite** как сборщик
- **React Router** для маршрутизации с guards (`PrivateRoute`, `RoleRoute`)
- **MobX** для глобального состояния (Root Store Pattern)
- **MSW** (Mock Service Worker) как мок-сервер — перехватывает REST-запросы и эмулирует ответы API
- **WebSocket** для чата в реальном времени

## 🚀 Быстрый старт

### Требования

- Node.js ≥ 18
- npm ≥ 9

### Установка

```bash
git clone <repo-url>
cd grit
npm install
```

npm install из корня установит зависимости для всех пакетов и создаст симлинки между workspace-пакетами.

```bash
npm run dev
```

### Storybook UI-кита
```bash
cd packages/ui-kit
npm run storybook
```

### Сборка
```bash
npm run build
```

### Проверка типов
```bash
npm run type-check
```

### Линт
```bash
npm run lint
```

### Разделение ответственности между пакетами
**ui-kit** — только визуальные компоненты и тема, без бизнес-логики

**toolkit** — чистые хуки и утилиты, без React-компонентов

**types-kit** — только типы, конфиги и контракты

Такое разделение даёт чистые границы и позволяет позже вынести любой пакет в отдельный репозиторий через git filter-repo без потери истории.

## 📂 Соглашения
**Коммиты**: Conventional Commits (feat:, fix:, chore:, refactor:)

**Ветки**: main — стабильная, feat/*, fix/* — рабочие

**Стиль кода**: ESLint + Prettier, автоформат при коммите через Husky + lint-staged

**Типизация**: строгий TypeScript, any запрещён (кроме крайних случаев с комментарием)
